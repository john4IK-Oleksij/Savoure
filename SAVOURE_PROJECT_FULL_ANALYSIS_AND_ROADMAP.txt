ВСТУПНЕ СЛОВО ВИКЛАДАЧА:
Перед вами не просто звіт про виконання завдань, а глибокий інженерний розбір еволюції проєкту Savoure. 
Створення комерційного веб-сервісу для ресторанного бізнесу преміум-сегмента вимагає балансу між двома
світами:
1. Бездоганним клієнтським досвідом (естетика французького fine dining, плавний UI, нуль зайвих бібліотек,
   миттєва реакція інтерфейсу).
2. Залізобетонною надійністю бекенду та бекстейджу (захист критичних ролей персоналу від випадкового видалення,
   інтуїтивна інтерактивна схема зали для хостес і менеджерів, наочний стоп-лист для шеф-кухаря, сувора
   безпека конфіденційних даних та надійна обробка винятків).

Нижче представлено дорожню карту з 8 детальних ітерацій. Кожна ітерація розбита на 3 послідовні інженерні
кроки, з детальним аналізом файлів, зв'язків, безпеки та архітектурних нюансів.

ІТЕРАЦІЯ 1: ІНФРАСТРУКТУРА, СЕКРЕТИ, ХОСТИНГ ТА БРЕНДОВИЙ СТИЛЬ SAVOURE
----------------------------------------------------------------------------------------------------
Крок 1.1: Контейнеризація та конфігурація середовища продакшну (Docker, Gunicorn, WhiteNoise).
Крок 1.2: Безпека облікових даних, динамічна маршрутизація портів Railway та ізоляція секретів.
Крок 1.3: Глобальна айдентика бренду — відмова від сторонніх іконок на користь автентичної Ейфелевої вежі.

* Файли, що створені / змінені:
  - Dockerfile (створено/налаштовано)
  - config/settings.py (конфігурація безпеки, WhiteNoise, DB URL)
  - templates/_eiffel_icon.html (створено)
  - templates/admin/base_site.html (налаштовано брендинг Backstage)
  - static/assets/img/favicon.ico (брендовий favicon)

* Що містять файли та за що відповідають:
  1. Dockerfile: Базується на легкому python:3.12-slim. Встановлює залежності, збирає статику WhiteNoise,
     створює директорії для медіа-файлів страв та стартує Gunicorn через sh -c з динамічним $PORT Railway.
  2. config/settings.py: Впроваджено dj_database_url для автоматичного перемикання між локальною SQLite
     та продакшн PostgreSQL/MySQL. Налаштовано WhiteNoise зі стисненням та кешуванням (CompressedStaticFilesStorage).
     Усі чутливі змінні (SECRET_KEY, DATABASE_URL, DEBUG) читаються суворо з середовища (.env / Railway Variables).
  3. templates/_eiffel_icon.html: Високоточний векторний SVG-контур Ейфелевої вежі. Приймає параметри
     icon_size та icon_fill, що дозволяє перевикористовувати символ бренду скрізь: від кнопок до таблиць адмінки.

* Де імпортуються та що експортують:
  - Dockerfile експортує фінальний образ для Railway.
  - _eiffel_icon.html імпортується в base_site.html, delete_confirmation.html, change_list.html через
    тег {% include "_eiffel_icon.html" with ... %}.

* Що робить виконання правильним та безпечним:
  - Безпека: Жодних хардкод-паролів, API-ключів чи секретних ключів у репозиторії. Файл .env додано до .gitignore.
  - Обробка помилок: Якщо зовнішня база даних недоступна, dj_database_url має безпечний fallback на локальну базу.
  - Продуктивність: WhiteNoise віддає статику напряму через Gunicorn без необхідності окремого Nginx на базовому тарифі.

РОЗДІЛ III. АНАЛІЗ БЕЗПЕКИ ТА НАДІЙНОСТІ (SECURITY AUDIT)
====================================================================================================

1. Відсутність хардкоду та конфіденційних даних:
   - Жоден файл проєкту не містить паролів до БД, секретних токенів чи персональних даних гостей.
   - Усі чутливі змінні середовища конфігуруються через захищені змінні хостингу Railway (Environment Variables).

2. Захист від атак веб-додатків:
   - Cross-Site Request Forgery (CSRF): Кожна форма на сайті (бронювання, контакти, підписка)
     захищена унікальним токеном {% csrf_token %}.
   - Cross-Site Scripting (XSS): Тексти, що вводяться користувачами (імена, коментарі, побажання),
     проходять суворе автоматичне екранування Django Template Engine та format_html().
   - SQL-ін'єкції: Усі вибірки виконуються виключно через безпечний Django ORM із параметризованими запитами.
   - Reverse Tabnabbing: Посилання target="_blank" супроводжуються атрибутом rel="noopener noreferrer".

3. Надійна обробка помилок (Error Handling):
   - Утиліти роботи з датами використовують безпечні ASCII-формати, що унеможливлює збої кодування locale
     на серверах Linux та хостах Windows.
   - Дублікати адрес електронної пошти в розсилці коректно перехоплюються через IntegrityError / get_or_create(),
     інформуючи гостя без викидання 500-ї помилки.
   - Відсутність збоїв через відсутні поля у моделях (виправлено GroupAdmin).
